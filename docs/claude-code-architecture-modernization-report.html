Historical snapshot — evidence frozen 2026-08-06

The redesign replaces accumulated workarounds with current native Claude Code contracts and stronger deterministic evidence.

What materially improved

The configuration now relies on native skill discovery, native ToolSearch, structured hook execution, bounded agents, fresh worktrees, fail-closed settings protection, reversible rollback, and executable release qualification checks. Receipt creation, connection status, and transcript presence are treated as evidence inputs—not as proof that work succeeded.

Keep model context short and discoverable. Enforce only deterministic invariants in hooks. Verify artifacts and runtime state before declaring success.

Claude Code and the local architecture co-evolved

This is the cumulative story behind the individual releases: the model became a more capable operator while Claude Code became a managed agent runtime. At the same time, the local architecture was learning from real use. Their ownership boundary kept moving.

The architecture was not arbitrary complexity

Claude Code began in February 2025 as a limited research preview with a minimal terminal surface: an agent that could inspect a repository, edit files, run commands, and use Git. Early adopters still had to decide how reusable context, routing, supervision, state, and organizational trust should work around it.

When this repository's first full configuration landed on 22 February 2026, it captured accumulated operating experience around the runtime that existed then. Over the following months, domain agents became a generic worker; repeated misses became routing and memory; platform failures became hook launchers and worktree guards; session loss became checkpoints and receipts. In parallel, Anthropic kept deepening the native versions of many of those responsibilities. The modernization is therefore a boundary correction—not a repudiation of the learning that produced the architecture.

Curve one The model became a better operator

Hybrid reasoning, parallel tool use, longer horizons, stronger instruction following, memory, and larger context made fixed thinking budgets and repeated prompt scaffolding age quickly.

Curve two The product became an agent runtime

Skills, plugins, hooks, MCP, ToolSearch, subagents, worktrees, sandboxing, durable sessions, diagnostics, and telemetry moved execution mechanics into Claude Code itself.

Feb–Apr 2025

A powerful primitive

The research preview paired an increasingly capable reasoning model with direct terminal agency. Its minimal initial surface exposed raw power, but provided few native facilities for reusable context, delegation, lifecycle, or enterprise governance.

Natural local response: build CLAUDE.md, reusable instructions, routers, approval and validation hooks, and external memory around the primitive.

May–Oct 2025

From CLI to connected workspace

General availability with Claude 4 brought IDE and GitHub Actions workflows; remote MCP standardized connections; Claude Code 2.0 added checkpoints and more autonomous operation; sandboxing moved protection closer to the process boundary.

The boundary shifted: editor integration, remote connections, recovery, and basic containment no longer had to be wholly user-built.

Oct 2025–Jan 2026

Extensibility became a product

Agent Skills made expertise discoverable and progressively loadable. Plugins began packaging skills, agents, hooks, and MCP servers as a supported unit, with native installation and lifecycle management rather than a loose collection of dotfiles.

Overlap appeared: custom registries, keyword routers, cache edits, and ambient instruction injection began duplicating an upstream extension system.

Feb–Apr 2026

One agent became a fleet

Building on already-available subagents and background tasks, agent teams, maturing worktree isolation, Auto mode, richer context handoffs, and evaluator patterns turned a conversation into an orchestration substrate. Anthropic's own harness guidance captured the core maintenance problem: every scaffold encodes an assumption about what the model cannot yet do, and those assumptions can expire quickly.

Natural local response: generic agents, context forks, receipts, workflow gates, and isolation were sensible bridges. As native contracts matured, some bridges became a second scheduler and state machine.

May–Jun 2026

The contracts firmed up

Agent views and goals made delegated work visible. Structured hook arguments, plugin dependencies and context estimates, component-level usage attribution, richer subagent feedback, MCP health handling, managed version policy, and OpenTelemetry made the runtime more inspectable and governable.

Bridges became liabilities: shell-string wrappers, heuristic routers, plugin cache mutation, connection badges, and home-grown attribution could now conflict with stronger native contracts.

Jul–Aug 2026

Native did not mean finished

Agent concurrency and nesting caps, stricter sandbox networking, credential masking, transcript-write warnings, richer MCP failures, forked worktrees, and immediate plugin activation made the substrate safer and easier to diagnose. The rapid fixes for worktree escape and a background-task hook bypass also showed why a native feature still needs a qualified version floor.

Durable local role: pin and qualify the runtime; retain organizational invariants, rollback, semantic acceptance, and independent verification rather than reimplementing the runtime.

The architectural half-life got shorter

A workaround could be correct when introduced and harmful a few releases later. A router can defeat progressive disclosure; a trimmer can hide output Claude Code now persists safely; a prompt hook can burn the context a larger model would otherwise use; a custom workflow can invent a weaker meaning of “complete.” The recurring maintenance question is no longer only “does this work?” It is also “does Claude Code now own this layer?”

Anthropic's containment retrospective adds an equally important limit: model instructions and repeated approvals are probabilistic and fatigue-prone, while environment boundaries and system primitives can be enforced. Native mechanics should replace duplicate glue, but not domain authority, consequential-action policy, evidence quality, or independent tests.

Then

Make the agent operational

Supply discovery, routing, delegation, persistence, recovery, packaging, and enough safety around a powerful but thin terminal agent.

Now

Govern the native runtime

Configure supported contracts, bound execution, pin qualified versions, observe failures, and remove mechanisms that compete with upstream behavior.

Still local

Prove what matters

Own organizational policy, domain knowledge, irreversible-action authority, expected artifacts, semantic acceptance, rollback evidence, and regression detection.

The model frontier moved under the architecture

Claude evolved from a model that benefited from explicit reasoning scaffolds into a family of long-horizon agents that allocate their own thinking, delegate readily, and increasingly self-check. The useful local role shifted from prescribing cognition to bounding execution and proving outcomes.

Architecture should follow behavior, not model branding

Early Claude Code paired Sonnet 3.7 with manual extended-thinking budgets and a simple planning scaffold. By Opus 5, thinking is on by default, effort is the primary control, one million tokens is the normal context window, and Anthropic explicitly says the model may delegate and self-verify without being told. Instructions that once compensated for model limits can therefore become duplicated work, excess narration, or conflicting constraints.

The answer is not to trust each stronger model more broadly. It is to remove prompt-level duplication while retaining external controls: scope, authority, isolation, typed failure handling, artifacts, tests, runtime checks, and rollback. Those controls verify the world rather than asking the same model to agree with itself.

Not every “model regression” is a model regression

Anthropic's 23 April quality postmortem traced reports of worse Claude behavior to Claude Code changes in default effort, preservation of prior thinking, and response presentation—not to the underlying API model. The architecture must therefore record the whole execution tuple: Claude Code version, requested and effective model, effort, provider, context state, prompt/rule revision, tools, and outcome.

What the local transcripts actually prove

The fixed ten-day snapshot ending 5 August is dominated by current models, so it cannot tell a clean 3.7-versus-5 story. It does reveal the operational contracts that remain necessary even as model capability rises.

  • Main-thread assistant messages were 38,691/40,660 (95.2%) Opus 5; child messages were 9,846/10,014 (98.3%) Sonnet 5. That is evidence of routing and workload shape, not a quality ranking.
  • All 16 native Agent calls came from Opus 5 parents, yet substantive child artifacts ran on Sonnet 5 or Sonnet 4.5. Only one call explicitly requested a model and none requested effort.
  • Workflow defaultModel did not reliably attest effective model or effort. Exact per-agent totals depend on logical-attempt deduplication, so they are excluded from the quality conclusion.
  • All 39 workflow receipts said “completed,” yet 4 contained 16 final logical errors; the 2 wholly failed receipts are a subset of those 4. All 16 errors explicitly reported “Prompt is too long,” measuring a context/harness failure—not inferior reasoning.
  • Therefore the defensible conclusion is about provenance and acceptance semantics—not that one model caused better or worse results.
01 · Provenance

Record the effective tuple

Capture requested and effective model, effort, provider, context class, Claude Code version, fallback/refusal state, and prompt revision per parent and child.

02 · Qualification

Qualify every model movement

Run a fixed task-family regression set before changing a pin or alias. Use exact IDs for critical automation and evals; reserve aliases for interactive sessions with a qualification gate. Compare artifacts, correctness, tool errors, fan-out, latency, tokens, refusals, and cost—not vibes.

03 · Thinking

Use effort, not fossilized budgets

Remove fixed thinking-token controls on current models. Sweep effort by task family, allow per-session choice, and verify that requested child effort actually propagated.

04 · Prompting

Keep a stable core and thin overlay

Keep concise objectives, authority limits, non-goals, and expected artifacts. Qualify only a thin model-specific overlay: Opus 5 may need duplicate verifier prompts removed, while Fable long runs still need evidence-grounded progress. A/B either change.

05 · Execution

Bound stronger agency

One-million-token context and stronger delegation do not justify ambient bloat or unbounded fleets. Cap child count, nesting, duration, context transfer, and consequential actions.

06 · Acceptance

Keep independent oracles

Model self-checks are useful evidence, never the final oracle. Require expected files, tests, schemas, runtime state, negative cases, and recoverable rollback; treat refusal and fallback as typed outcomes.

Always-on context

CLAUDE.md, scoped rules, platform notes, small indexes—not security boundaries.

On-demand capability

Native skill discovery and bounded agent dispatch without a keyword router.

External tools

Regression, mutation, drift, manifest, skill, plugin, and platform checks.

L08

Distribution & deploy

Canonical source, generated marketplace, installer, preserved live config.

Design decisions

The review did not equate “new” or “popular” with “better.” Each proposal received a disposition.

Adopt

  • 2.1.223 floor and advisory sweep
  • Structured deterministic hooks
  • Native skills and ToolSearch
  • ConfigChange and rollback
  • Bounded agents and artifact verification

Direct qualification

  • Disposable candidates only
  • Same-run regression and mutation evidence
  • No live edit while evidence is pending
  • No calendar or session-count promotion

Defer

  • OTel MCP/plugin schema projection
  • Plugin and sandbox changes not yet qualified
  • Global thresholds without usage data

Reject / remove

  • Canary, staged, trial, and time-based rollouts
  • Ambient routers and prompt injectors
  • Hard MCP truncation
  • Background Skill forks by default
  • Receipt-exists success
  • Aggressive dirty-worktree cleanup

Why these changes were chosen

The evidence combined current first-party guidance, recent public lessons, repository behavior, and private session telemetry.

External research

  • Claude Code releases 2.1.129–2.1.223 and the preceding three months of change history.
  • Every public Claude-family release since the Claude Code preview, plus current model migration, prompting, lifecycle, refusal, and tokenizer guidance.
  • Current Anthropic guidance for best practices, hooks, permissions, subagents, plugins, and MCP.
  • First-party GitHub security advisories and current architecture-relevant issues.
  • Sixteen community searches and eighteen deeper reads across Reddit, blogs, forums, an empirical paper, and indexed X threads.
  • Community claims remained hypotheses until corroborated by first-party or local evidence.

Local behavior evidence

  • 542 transcripts in a fixed ten-day snapshot: 134 main and 408 child sessions.
  • 39 workflow receipts; 4 contained final logical errors and 2 were entirely failed despite “completed.”
  • Native Agent calls: 8 ordinary completions, 4 desired isolation blocks, 4 context/background failures.
  • 2,264 MCP calls with 141 errors; 450 ToolSearch calls, 436 exact select: queries.
  • A hard-truncated MCP response was immediately requested again—evidence against custom truncation.

Reviewed boundaries and accepted risk

The report separates what was changed from what was intentionally left alone or remains unproven.

Owner-accepted bearer-token exception
The embedded bearer value was left unchanged by explicit owner direction. Validity testing, rotation, history rewriting, and downstream access-log review are outside this modernization. Its value is not reproduced in this report.
Externally managed telemetry is a live P0
Repository templates now require metadata-only OTel and reject any enabled content flag. The winning macOS managed profiles were separately inspected and currently enable prompt, response, tool, and raw API-body content. Repository or local settings cannot override that higher-precedence policy; the Jamf/MDM owner must reconcile it, and backend receipt remains unverified.
Managed startup floor is not deployed
The repository floor, installer preflight, and native installation are aligned at 2.1.223, but the administrator-managed requiredMinimumVersion policy is still undeployed. minimumVersion protects repository installation and qualification; it does not substitute for the managed startup control.
Native Windows is not yet proven
Windows path and Git-Bash behavior passed structural and simulated tests. An actual hosted windows-2022 workflow remains the gate before a native-Windows claim.
Remote MCP and authenticated product state
Authenticated Claude.ai/Remote Control state and every live remote-MCP inventory were not proven from this host. Critical servers require current-session positive and negative direct probes before use in child tasks.
Transcript and community coverage
The transcript review is a fixed ten-day snapshot, not all history. Valid JSONL does not prove every assistant message was stored. Direct X API search was unavailable; indexed original URLs were corroborated elsewhere. Popularity was never treated as effectiveness.
Deliberately deferred operational measurements
Per-server MCP latency, disposable plugin/sandbox qualification, child remote-MCP inheritance, and OTel correlation fields remain measured follow-ups—not hidden source defects. No live change is applied merely to observe it.
