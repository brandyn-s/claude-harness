**Statusline rate limits (v2.1.80+)**: Statusline scripts now receive a `rate_limits` field with `five_hour` and `seven_day` windows containing `used_percentage` and `resets_at`. Available for claude-hud display. **Note**: `used_percentage` is calculated against the wrong context window for 1M models (#39467) — shows ~68% at 77K tokens instead of ~8%. Related to #36014.

**`--bare` flag (v2.1.81+)**: For scripted/programmatic `-p` calls, `--bare` skips hooks, LSP, plugin sync, and skill directory walks. Requires `ANTHROPIC_API_KEY` or `apiKeyHelper`. Auto-memory fully disabled. v2.1.86 fixed `--bare` dropping MCP tools in interactive sessions and silently discarding messages enqueued mid-turn.

**`TaskOutput` deprecated (v2.1.83)**: Use `Read` on the background task's output file path instead. Background agent tasks also no longer stay stuck in "running" state when git/API calls hang during cleanup.

**`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` (v2.1.83)**: Set to `1` to strip Anthropic and cloud provider credentials from subprocess environments (Bash tool, hooks, MCP stdio servers). Defense-in-depth against credential leakage. **KEEP AT `0` — do NOT re-enable (3rd occurrence guard).** Any non-empty-and-not-`0` value force-downgrades the permission mode to `default` and prints "Permission mode forced to default" on EVERY launch, and (2026-07-24) this now also hits **Claude Desktop**, whose embedded Claude Code reads the same `~/.claude/settings.json`. History: added #489, deliberately removed #570 (same symptom), silently re-added #897 inside a 3-week salvage batch tagged "defense-in-depth", set to `0` here. Verified 2026-07-24: `"0"` suppresses the downgrade (the binary parses the VALUE, not mere presence); deleting the key entirely also works, but `"0"` is explicit and matches settings.example.json. Note `--settings <file>` MERGES with user settings, so omitting the key from a CLI settings file does NOT override a user-level value. **Counter-argument on record:** a concurrent session argued for RETENTION the same day (claude-knowledge-base #1234) on the grounds that #570's "no additional security benefit" claim was falsified by three `CONFLUENCE_API_TOKEN` process-listing leaks. That was reviewed and the disable decision stood (KB #1236): two of the three leaks (2026-05-19, 06-20) POSTDATE the 2026-05-16 re-add, so scrub-on did not prevent them — the vector is the launcher's own argv, which scrub never touches, and the control that closed the class is `bash-security-guard.py`'s block on wide process listings. Read `topics/claude-code-security-posture.md` before re-litigating; the decision record lives there, not in this file's `git log`. If scrub is ever re-enabled, the Desktop-side fix is `epitaxy-folder-permission-mode` -> `default` (not leaving it at `auto`).

**`DISABLE_UPDATES` (v2.1.118)**: Stricter than `DISABLE_AUTOUPDATER` — blocks ALL update paths including manual `claude update`. Relevant for locked-down DoD/GovCloud workstations with enforced version pinning.

**Hook `type: "mcp_tool"` (v2.1.118)**: Hook entries can invoke MCP tools directly without spawning a shell subprocess, reducing per-hook latency and child-process count. Schema not yet captured — audit current shell-based MCP invocations in `~/.claude/hooks/` before migrating.

## Current automatic-update policy — 2026-08-08

Automatic updates are intentionally enabled. Repository settings leave
`autoUpdatesChannel` unset, using the currently documented `latest` default,
and intentionally omit `DISABLE_AUTOUPDATER`, `DISABLE_UPDATES`, and
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`. The user setting
`minimumVersion: 2.1.226` prevents updater downgrades; it does not block
startup. The managed template's `requiredMinimumVersion: 2.1.226` is a
separate managed startup floor, and the template is not evidence that an
administrator deployed it.

fresh-session qualification checks against the behavior the architecture
depends on. Static repository validation cannot prove that an external shell,
launcher, or managed profile has not injected an update blocker. Re-check the
effective environment after every update. Current first-party contracts:
[settings](https://code.claude.com/docs/en/settings) and
[updates](https://code.claude.com/docs/en/setup).

## grep shim inverts exit code with `-v` + suppressed output — 2026-08-22 (v2.1.240, #88802)

Inside a session, the grep shell-snapshot shim answers a FILE-level question
instead of a line-level one when `-v` is combined with suppressed output (`-q`
or `>/dev/null`): it returns 0 iff at least one input contains ZERO matching
lines. Real grep returns 0 iff at least one LINE fails to match. Fails silently
in both directions. Reproduced on this host on v2.1.240 (shim=1 vs
`command grep`=0 on identical input, gather-claude run 2026-08-22b). Repo audit
found zero `grep -qv`/`-vq` in hooks/bin/scripts — the exposure is inline
agent-typed conditionals. Rule: when `-v` decides a branch, use `command grep`
or drop the suppression. Upstream: anthropics/claude-code#88802 (open); retire
this note when it closes COMPLETED and a local re-probe matches real grep.
