## Known Constraints

- The graph is a heuristic prior. A high confidence number cannot override an
  explicitly low/fuzzy resolution strategy.
- Code-graph's exact `index_identity` schema and digest algorithm are
  load-bearing:
  `code-graph/internal/indexidentity/identity.go:29-92`,
  `code-graph/internal/store/store.go:490-501`, and
  `code-graph/internal/tools/index_identity.go:84-91`.
- The first implementation accepts only clean Git source checkouts. It does not
  duplicate code-graph's dirty-worktree fingerprint algorithm.
- Direct SQLite access is read-only compatibility glue. Schema mismatch,
  missing identity, lock contention, or in-progress identity state fails
  closed.
- Semantic code-search results are discovery leads only until code-search
  exposes the same identity envelope.
- PSM contains two real `controlsd` packages, an `ebrake`/`ebraked` alias,
  an `sbfd` lib/bin collision, and a Go `auth-gateway`/Nix `authgateway` join.
- The existing Nix service metadata registry is incomplete, so it cannot be
  the resolver's only source.
- Canonical source is a separate skill (not included in this export)**`. `marketplace/**` is generated by
  `python3 scripts/build-marketplace.py`.
- Runtime skill commands use
  `python3 ~/.claude/a separate skill (not included in this export); shipped Python
  resolves bundled assets from `Path(__file__).resolve()`.
- CI is cross-platform. Tests cannot require the user's home paths, the live
  PSM database, or network access.
- This plan does not modify live `~/.claude`, live `~/.agents`, PSM,
  `example-compliance-repo`, or any index.

## Dependency Failure Analysis

**Dependency: Git CLI**

- If absent: identity capture fails before bundle/verify.
- If timeout/error: return `SOURCE_IDENTITY_UNAVAILABLE`.
- If malformed output: reject; never substitute `origin/main` or a cached SHA.

**Dependency: code-graph SQLite schema**

- If unavailable: target resolution from source can still explain candidates,
  but bundle/verify cannot publish.
- If locked: one bounded read attempt, then structured hold.
- If schema drifts: validate required columns/tables and name the mismatch.
- If data is empty: report coverage/identity; never interpret as no behavior.
- If it changes during extraction: use one read transaction, compare identity
  before/after, and publish no new final receipt.
- If its identity schema version is unknown: fail closed until checked-in
  code-graph compatibility vectors prove the shared digest contract. Producer
  binary provenance is not persisted and must be reported as unavailable.

**Dependency: source manifests**

- If malformed: skip that candidate with a diagnostic; if it was the only
  candidate, return not-found/incomplete rather than guessing.
- If Nix syntax is outside the bounded join parser: do not create an alias;
  accept an explicit qualified source target and report deployment coverage
  `unknown`.

**Dependency: code-search**

- If unavailable: generation loses semantic discovery assistance but
  deterministic bundle/verify behavior is unchanged.
- If stale or unidentifiable: results cannot enter publish evidence.

**Dependency: marketplace builder**

- If it fails: canonical source remains authoritative; do not hand-copy.
- If it changes unrelated generated files: inspect the builder/version ledger
  and separate expected from unrelated drift before commit.

## Interview Findings

The `interview` skill challenged seven load-bearing assumptions. All were
resolved before Phase A:

1. **What prevents a generator from forging `reviewer_identity`?** Nothing in
   an unsigned JSON record authenticates the reviewer. If treated as authority,
   unsupported claims could self-promote. Amendment: an unsigned, hash-valid
   record is tamper-evident only and can reach `REVIEWED_DRAFT`, never
   `PUBLISH`. Test: `forged_review_receipt`.
2. **What prevents a mixed source/graph snapshot?** Separate identity and fact
   reads would permit a concurrent source change or reindex. Amendment: one
   explicit SQLite read transaction plus source/index identity capture before
   and after extraction; any change replaces no output. Test:
   `snapshot_changed_during_read`.
3. **How does the Python identity port stay compatible with Go?** Source
   similarity is not a contract as code-graph evolves. Amendment: support only
   identity schema version 1, check code-graph's checked-in Go compatibility
   vectors, fail closed on unknown schema versions, and report that producer
   binary provenance is unavailable because code-graph does not persist it.
   Test: `identity_compatibility_vectors`.
4. **Can Markdown structure bypass the coverage scanner?** A generic scope
   marker could hide facts, and line heuristics could mishandle tables or
   multiline blocks. Amendment: use a closed block grammar with narrow
   structural exemptions and no prose waiver. Test:
   `markdown_coverage_mutations`.
5. **Is replacing a populated artifact directory really atomic on every CI
   platform?** No portable non-empty directory swap is assumed. Amendment:
   same-directory temporary files plus `os.replace`, with `receipt.json`
   written last as the only commit marker. A stale receipt cannot validate
   mixed hashes. Test fault injection after each write/replace.
6. **Can caller/callee identity prove the right invocation without a
   callsite?** No; repeated calls from the same caller remain ambiguous.
   Amendment: publishable call claims require exact callsite file and line;
   missing/non-unique locations are unsupported. Test two calls with one
   caller/callee pair.
7. **Can constant metric text stay green after tests disappear?** Yes.
   Amendment: maintain an explicit contract inventory consumed by tests and
   derive metrics from that inventory only after the full suite passes.
   Removing or deselecting a DG/resolver case must fail inventory equality.
