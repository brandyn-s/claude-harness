Generated by `bin/skill-description-eval.py report` from `results-2026-09-04-xhigh.json`. Do not hand-edit; re-run the eval to refresh. Refresh command: `bin/skill-description-eval.py report --results results-2026-09-04-xhigh.json --compare results-2026-09-04-low-current-table.json --compare results-2026-09-04.json --faithful faithful-2026-09-04.json`.

## Method

- Routing model: `claude-fable-5-1` at effort `xhigh`, run 2026-09-04. One request per corpus item, no repeats.
- Routing table: one cached system prompt listing every model-visible skill as `name: description + when_to_use` cut at 1,536 characters (the runtime listing contract in `scripts/validate-skills.py` A2). The answer is constrained to one skill name or `none`.
- Corpus: 3 positives per skill generated by `claude-sonnet-5` from the SKILL.md body with the frontmatter removed, plus 30 hand-written generic requests labelled `none`.
- Cost of the routing run: $3.09 (264 requests; corpus generation $1.21).
- A positive that routes to `none` is a miss the description caused; one that routes to another skill is a collision. A negative that routes anywhere is a false fire.

## Caveats

- One run per request at effort `xhigh`; treat single-item differences as noise and patterns (a skill at 0/3, a pair confused repeatedly) as signal.
- The router sees only the listing text. In the runtime the model also sees the conversation, tools, and rules, so absolute rates will differ; relative ranking is the evidence.
- Positives were written from the skill body, so a low recall means the body promises something the description does not say, or another description claims it first.
