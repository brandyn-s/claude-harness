# AGENTS.md

Orientation for an AI agent working **on** this repository.

This repo is not an application. It is a **Claude Code harness**: configuration
that executes. Editing a file here changes how an agent behaves, so the ordinary
"read code, make change" loop has an extra requirement — you must know whether the
thing you are editing is *enforced*, *advisory*, or *generated*.

Humans should start at [README.md](README.md); it explains why the repo exists.
This file exists so you do not have to infer the machine-readable surface by
grepping.

---

> **Enforcement edges are DERIVED, not declared.** `manifests/compile.py` computes each rule's graph-only `enforced_by` from `settings.json` wiring intersected with the hook manifests' own `enforces`; rule source manifests do not store a back-reference. `--check` rejects a coverage label contradicted by those derived edges. Before this existed, 20 edges had drifted — rules claiming enforcers that were never wired, and wired hooks the graph said did not exist — so `unenforced_rules` and `enforcement_chain` returned confident wrong answers in both directions.

## 1. Orient: five layers, ranked by whether you can ignore them

| Layer | Path | Loads | Can the model ignore it? |
|---|---|---|---|
| Hooks | `hooks/` | on matching tool calls | **No** — the runtime enforces them |
| Ambient rules | `rules/*.md` | always, in context | Yes (they are text) |
| Path-scoped rules | `rules/*.md` with `paths:` | when a matching file is touched | Yes |
| Skills | `skills/<name>/SKILL.md` | on invocation | Yes |
| Agents | `agents/*.md` | on dispatch | Yes |
| Reference | `docs/rule-reference/`, `rules/incidents/` | on demand | Yes |

Only the first row can *stop* anything. If you are asked to make some behaviour
impossible, a rule is the wrong answer and a hook is the right one. See
[ARCHITECTURE.md](ARCHITECTURE.md) for the reasoning.

## 2. Do not edit: generated trees

| Path | Generated by | Notes |
|---|---|---|
| `marketplace/**` (~1,024 files) | `scripts/build-marketplace.py` | Self-contained plugin bundles. Edit the ORIGINALS in `skills/`, `hooks/`, `agents/`, `bin/`. Marked `linguist-generated`. |
| `.claude-plugin/marketplace.json` | same | Catalog. |
| `manifests/graph.json` | `manifests/compile.py` | Not committed. Compile it before querying (below). |

`marketplace/` duplicates content on purpose: an installed plugin is copied to a
cache and cannot reference files outside its own directory, so each bundle must be
self-contained. A change to a skill is not shipped until the bundles are rebuilt,
and CI fails if they are stale.

## 3. Query the graph instead of grepping

The repo compiles its own components into a queryable graph. This is the fastest
way to answer structural questions and it is easy to miss.

```bash
python3 manifests/compile.py --root .            # build manifests/graph.json
python3 manifests/query_engine.py --root . coverage
```

Available queries:

| Query | Answers |
|---|---|
| `coverage` | how many components have manifests (currently 180/192) |
| `enforcement_chain` | which hook actually enforces a given rule |
| `unenforced_rules` | rules with **no** mechanical backing — advisory only |
| `hooks_for_tool <Tool>` | every hook that fires for a tool |
| `full_session_hooks` | the session-lifecycle hook set |
| `depends_on` / `depended_on_by` | component edges |
| `impact_of_removal <id>` | what breaks if you delete something |
| `context_for_task` | which components a task should load |
| `skills_by_category`, `skills_requiring_auth`, `auth_requirements` | skill inventory slices |
| `constraint_check` | declared constraints vs source |

Validate before you commit:

```bash
python3 manifests/compile.py --root . --check --strict-semantic --no-reindex
```

It exits non-zero on dangling references and manifest/source drift. **Run it
after touching any skill, hook, or rule.**

## 5. Verify your change

```bash
pip install -r requirements-dev.txt
python3 scripts/run-tests.py --selftest      # prove the gate can fail
python3 scripts/run-tests.py                 # ~3,900 tests, ~10 min
python3 scripts/run-tests.py -k hooks        # one directory, fast
```

Three things about the runner that will otherwise waste your time:

- **A root-level `pytest` cannot work here.** Test modules import their own
  `conftest` by name (needs prepend import mode) and two test files share a
  basename (which prepend mode cannot collect together). `--import-mode=importlib`
  fixes the second and breaks the first. Run per directory; the runner does this.
- Every discovered test directory must pass; there is **no tolerated-failure
  baseline** (the earlier known-failing baseline was retired once it reached zero).
- **Running the tests: do it outside the Claude Code Bash sandbox.** Some hook
  tests write probe files under `hooks/`, open local sockets and call `ps`, all of
  which the sandbox denies, so a run inside it reports environment-caused
  failures. Run `python scripts/run-tests.py` from a plain terminal.

## 6. Invariants — breaking these silently breaks the repo

1. **The ambient rule corpus has a derived ceiling.** `manifests/ambient-budget.json`
   stores no ceiling; it is computed as
   `baseline_unconditional_bytes + sum(ledger[].bytes)`. Growing a `rules/*.md`
   therefore requires *appending a ledger entry* with a byte count and a reason.
   There is deliberately no number to edit. Adding `paths:` frontmatter exempts a
   rule from the count entirely — that is a real mechanism, not a loophole, but do
   not use it to dodge the budget.
2. **A hook must fail closed.** A guard that crashes and thereby permits the action
   is worse than no guard. Every hook needs a test in `hooks/test-hooks/`.
3. **Never weaken a gate to make it pass.** Narrowing a detector greens the build
   by reducing coverage. Baseline the known set and gate the delta instead.
4. **Pair every zero with a known-positive control.** A scanner reporting nothing
   and a scanner that is broken are indistinguishable without one. The CI
   `gitleaks` job does this to itself.
5. **Generated trees are outputs.** Never hand-edit `marketplace/`.

## 7. What is deliberately absent

This repo is a curated public export of a larger private configuration, so some
things are missing **by design** and are not bugs to fix:

- `agent-memory/topics/` ships **empty**. It held one file per operated system —
  inherently environment-specific. `agent-memory/README.md` documents the
  convention, which is the transferable part.
- **32 skills were removed** (tenant-bound provisioning, monitoring, compliance
  tooling). Some incident write-ups reference them; the lesson stands, the
  `/name` cross-reference does not resolve.
- `skills/_shared/repo-map.md` and `skills/_shared/linear-routing.md` are empty
  **templates** — fill them in for your environment; the column contract is the
  interface.

## 8. Conventions when adding something

- **A new hook**: add `hooks/<name>.py`, register it in `settings.json`, add
  `hooks/test-hooks/test_<name>.py`, add `hooks/manifests/` metadata if the layer
  uses it, then run `compile.py --check`.
- **A new skill**: `skills/<name>/SKILL.md` with `name`, `description`, and
  `when_to_use`. The `description` **is** the routing logic — say what triggers it
  *and* what should not. Combined `description` + `when_to_use` is truncated at
  1,536 characters in the skill listing, so put the key case first. Push detail
  into `references/` and deterministic helpers into `scripts/`.
- **A new rule**: keep the contract short enough to stay resident and put the
  narrative in `rules/incidents/` and the long form in `docs/rule-reference/`.
  Then append a budget ledger entry.
- **After any of the above**: `compile.py --check` and `run-tests.py -k <area>`.

## 9. House style for changes

- State what you measured, not what you assume. Findings in this repo cite
  file:line or an exact quote.
- A proposed fix needs its **precondition** named: confirming a problem is real
  does not confirm the remedy is possible.
- Prefer the smallest correct change. This repo's value is its specificity; a
  tidying pass that removes dated, measured detail removes the point.
