# Inventory management

## Default inventory

`canonical-2026-04-29` — 165 substantive frameworks (170 entries minus
5 cross-reference pointer stubs filtered by `len(body) > 200`). Lives
at `~/Documents/knowledge-base/research/2026-04-29-frameworks-master-inventory.md`.

The skill resolves `--inventory` arguments via:
- Path matching `inventories/*.meta.yaml` declarations
- Direct file path (absolute or relative to cwd)
- Default to canonical when no flag given

## Adding a new inventory

Step 1 — generate or curate the inventory file. Use the prompt at
`~/Documents/knowledge-base/research/2026-04-30-framework-dispatch-template-v2.md`
or write your own.

Step 2 — drop the file in `~/Documents/knowledge-base/research/`
(canonical KB location, not in skill dir).

Step 3 — write a metadata file in `inventories/<name>.meta.yaml`:

```yaml
name: source-B-llm-generated
source: claude-opus-4-7 fresh session, prompt from 2026-04-30
date: 2026-05-DD
file: ~/Documents/knowledge-base/research/2026-05-DD-frameworks-source-B.md
framework_count: 137

  Generated 9 functional buckets (vs canonical's 11):
  - Standpoint Enumerators
  - Constraint Imposers
  - Frame Collisioners
  - Subtractors
  - Provocateurs
  - Meta-Routers
  - Engineering Methods
  - LLM-Native Patterns
  - Apophatic / Negative

  HIGH: 62
  MEDIUM: 38

  Native buckets.
```

Step 4 — invoke the skill with `--inventory inventories/source-B-llm-generated`.

## Inventory comparison

When running meta-mode experiments across inventories:
- Same problem, same N, same model, same seed
- Vary only the inventory
- Compare per-RC endorsement, off-rubric novelty, bucket coverage

If results converge across inventories, the methodology is robust to
inventory choice. If results diverge, the inventory IS the
experiment — that's a finding.

## Bucket-coverage with non-canonical inventories

The canonical inventory has 11 buckets. Other inventories may have
different counts (9, 12, 15, etc.).

The cohort_sample script reads the bucket structure from the metadata
file and adapts:
- "1 per bucket" floor adjusts to the inventory's bucket count
- Default N stays 15 unless caller overrides
- If N < bucket count, sampling won't achieve full coverage; warn

For meta-runs comparing inventories, use a normalized N (e.g., 1.5×
bucket count) so each inventory gets proportional coverage.

## Pointer-stub filter

The canonical inventory has 5 cross-reference stubs (e.g., "2.24 Jain
anekanta-style sevenfold predication (already covered in 1.1)"). The
parser filters these via `len(body) > 200`. If a new inventory uses a
different stub format, update the filter in
`scripts/parse_inventory.py` or document the alternative format in
the inventory's metadata file.

## Canonical inventory caveat

The canonical inventory is curator-biased (the user wrote it). Per
F6 red-team residual #1, this isn't fixable at the skill level; it's
fixable only by running meta-mode comparisons against independent
inventories. Source-B and source-C slots exist for this exact
purpose.
